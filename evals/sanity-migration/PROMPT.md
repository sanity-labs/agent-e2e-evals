Our blog stores each post's `body` as a Markdown string and its `author` as a plain name. Write one Sanity content migration that converts `body` to Portable Text (headings, paragraphs, links, bold, italic and bulleted/numbered lists must survive) and `author` to a reference to an `author` document, with one author document per person. Names that differ only by letter case or leading/trailing spaces are the same person. Give the author document type a `name` field. Update the schema to match.

Posts also have `related`, a list of slug strings for other posts. Convert it to a list of references to those posts, and keep the list order. Every slug in `related` belongs to exactly one published post in the export; reference that published post, even when the link comes from a draft. Entries that are already references stay as they are.

The export also contains content release versions of posts (IDs starting `versions.`). Convert them in the same way as published posts and drafts, keeping their IDs, their release and their other fields unchanged. Author references always point to the published author document.

Some posts are already partly converted, and the migration must be safe to run more than once. It must be discoverable and runnable by the Sanity CLI. We'll test it offline against an export file. In this version of the migration tooling, finishing a read of the document list can remove the temporary export snapshot, so don't rely on reading it a second time. You may install dependencies while preparing the solution; the migration itself must not call the Sanity API or anything else over the network. Don't run it against a dataset. Sample documents are in `data/sample.ndjson`.
